# コードを書かずに始める評価駆動開発

> **日本語版オリジナルのワークショップです。** 原典 `anthropics/cwc-workshops` の翻訳ではありません。
> 考え方は原典の [`eval-driven-agent-development`](https://github.com/anthropics/cwc-workshops/tree/main/eval-driven-agent-development)
> を下敷きにしていますが、コード・ターミナル・API キーを使わずに体験できるよう作り直しています。

AI に何かを書かせたとき、「なんとなく良さそう」で済ませていませんか？
このワークショップでは、**AI の出力を「テストケース」と「採点表」で測り、点数を見ながら指示（プロンプト）を直していく**
という評価駆動開発（eval-driven development）の流れを、手を動かして体験します。

題材は、誰もが一度は悩んだことのある **「断りの返信」** です。
飲み会の誘い、お金の貸し借り、しつこい営業、頼まれごと――角を立てずに、でもはっきり断る文面を AI に書かせます。

## 対象と前提

| 項目 | 内容 |
|---|---|
| 対象 | AI を仕事や生活で使い始めた・使おうとしている方。プログラミングの経験は問いません |
| 所要時間 | 約60分（各ステップ15分） |
| 必要なもの | [claude.ai](https://claude.ai) のアカウント、スプレッドシート（Google スプレッドシート / Excel / Numbers のどれでも可） |
| あると便利 | 文字数カウントツール（ブラウザで「文字数カウント」と検索すれば出てきます） |

> Claude Code を使える方は、このフォルダを開いて「`step-1-criteria/PROMPT.MD` を読んで進めて」と頼めば、
> コピー&ペーストの手間を省けます。やることは同じです。

## 進め方

| ステップ | 時間 | やること | 得られるもの |
|---|---|---|---|
| [`step-1-criteria/`](step-1-criteria) | 15分 | 「上手な断り方」とは何かを言葉にする | 合格基準のメモ |
| [`step-2-testcases/`](step-2-testcases) | 15分 | 断りたい場面10件を確認し、自分の場面を足す | テストケース表 |
| [`step-3-grading/`](step-3-grading) | 15分 | 最初の指示（v1）で返信を作り、採点表で採点する | **ベースライン**（v1 の点数） |
| [`step-4-improve/`](step-4-improve) | 15分 | 失敗を分析して指示を1つずつ直し、採点し直して比べる | 改善した指示（v2, v3 …）と点数の推移 |

各ステップのフォルダにある `PROMPT.MD` が、そのステップで Claude に渡すプロンプトです。
`{{ … }}` の部分を指定のファイルの中身に置き換えて貼り付けてください。

解説ページ [`docs/guide.html`](docs/guide.html) には、評価駆動開発の考え方を図解でまとめています。

```
├── step-2-testcases/
│   ├── PROMPT.MD                   足りない場面を洗い出すプロンプト
│   └── testcases.csv               断りたい場面10件
├── step-3-grading/
│   ├── PROMPT.MD                   返信の生成 → 採点 の2つのプロンプト
│   ├── rubric.md                   採点表（チェック5項目＋スコア2項目）
│   └── scoresheet.csv              採点結果を貼り付けるシートのひな形
├── step-4-improve/

```

## このワークショップで持ち帰ってほしいこと

1. **「良い」は言葉にしないと測れない。** 測れないものは改善できない。
2. **ふつうの例だけで試すと、いざというとき困る。** 微妙な場面や例外こそテストケースに入れる。
3. **直す前に、今の点数（ベースライン）を記録する。** 比べる相手がいないと、良くなったか分からない。
4. **一度に変えるのは1か所だけ。** そして必ず全ケースで測り直す。どこかを直すと、別のどこかが悪くなることがある。
5. **採点係（AI）も間違える。** ときどき自分で採点して、ずれていないか確かめる。

この流れは、断りの返信に限らず、AI に繰り返し任せたい仕事なら何にでも使えます。
議事録の要約、メールの下書き、問い合わせへの回答、SNS の投稿文……。

## 専門用語との対応

開発チームと話すときや、さらに調べるときのために、対応する専門用語を載せておきます。

| このワークショップ | 専門用語 | 原典での対応 |
|---|---|---|
| テストケース表 | テストセット / eval set | `tasks.json` |
| 採点表のチェック項目（✅/❌） | コードによる採点 / code-based grader | `src/graders/code/` |
| 採点表のスコア項目（1〜5） | LLM による採点 / LLM-as-a-judge | `src/graders/judge/` |
| 最初の点数 | ベースライン / baseline | `npm run eval -- --baseline` |
| 直したら別のところが悪くなった | 退行 / regression | — |
| 指示（プロンプト） | システムプロンプト | `resources/agent.yaml` の `system` |
