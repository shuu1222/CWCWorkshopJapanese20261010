# ステップ2：テストケースを作る（15分）

## ねらい

AI を試すとき、つい「ふつうの例」で1〜2回試して満足してしまいます。
でも、AI が失敗しやすいのは、**一部だけ断りたい・理由を言いたくない・相手を傷つけたくない** といった微妙な場面のほうです。
このステップでは、AI を試すための「問題集」＝ **テストケース** を整えます。

## やること

1. [`testcases.csv`](testcases.csv) をスプレッドシートで開き、10件の場面と「上手な断り方のポイント」を読む（5分）
2. **自分が実際に断るのに困った場面** を1〜2件、`R11`, `R12` … として表に足す（5分）
3. 時間があれば、下のプロンプトで Claude に足りない場面を洗い出してもらう（5分）

> 「上手な断り方のポイント」は、採点のときの答え合わせに使います。
> 場面を足すときは、メッセージだけでなく「私の事情」と「ポイント」も必ず書いてください。

## Claude に渡すプロンプト

`{{ … }}` を [`testcases.csv`](testcases.csv) の中身に置き換えてから貼り付けてください。

```
AI に「断りの返信」を書かせる仕組みを試すために、テストケース（断りたい場面の例）を作っています。

## いまあるテストケース
{{ testcases.csv の中身 }}

お願い：
1. いまあるテストケースが、どんな種類の場面をカバーしているかを整理してください。
2. まだテストできていない場面のうち、AI が失敗しやすそうなものを5つ挙げてください。
3. それぞれについて、テストケースを1件ずつ作ってください。形式は既存の表と同じ CSV 1行にしてください。case_id は R11 から振ってください。
```

## ふりかえりの問い

- 自分で足した場面は、AI にとって難しそうですか？ それはなぜですか？
- 実際に使うなら、テストケースは **自分が本当に困った場面** から作るのが一番です。
  特に「AI に書かせたらイマイチだった場面」は、必ず入れておきたい財産です。
