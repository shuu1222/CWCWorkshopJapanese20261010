# ステップ4：測りながら直す（15分）

## ねらい

ベースラインが取れたら、いよいよ指示を直します。ここで大事なのは **「直す → 全ケースで測り直す → 比べる」を繰り返すこと** です。
気になった1件だけ試して「良くなった」と判断するのは禁物です。どこかを直すと、別のどこかが悪くなることがあります（退行）。

## 改善ループのルール

1. **失敗をグループ分けする。** 1件ずつ直すのではなく、「同じ原因で落ちている場面」をまとめる
2. **一度に直すのは1つの原因だけ。** まとめて直すと、どの変更が効いたのか（どれが悪さをしたのか）分からなくなる
3. **全ケースで測り直す。** 直したかった場面だけでなく、10件すべて
4. **ベースラインと比べる。** 合格数・平均が上がったか。**v1 で合格していたのに落ちた場面はないか**
5. **採点表も疑う。** 自分の採点とずれていたら、指示ではなく採点表のほうを直すべきかもしれない

## やること

1. 下の「プロンプト③」で、v1 の失敗を分析してもらう（3分）
2. 一番影響の大きい原因を1つ選び、指示に1〜3行書き足して v2 を作る（2分）
3. ステップ3の「プロンプト①」「プロンプト②」を v2 で実行し、`scoresheet.csv` に v2 の行を追加する（7分）
4. v1 と v2 を比べる（3分）。時間があれば v3 へ

> 指示を書き足すときは、Claude に「直した指示を全部書いて」と頼むより、
> **自分で1〜3行書き足す** ほうが、何を変えたのかがはっきりして学びが大きいです。

## プロンプト③：失敗を分析する

ステップ3の採点を行ったチャットの続きで実行すると、貼り付けが少なく済みます。

```
v1 の採点結果をもとに、失敗の原因を分析してください。

1. 不合格の場面を、失敗の原因が同じものどうしでグループに分けてください。
2. 各グループについて、「指示に何が書かれていなかったから起きたのか」を説明してください。
3. 指示 v1 に書き足すべきことを、効果が大きそうな順に3つ提案してください。それぞれ1〜3行の短い文にしてください。
4. その書き足しによって、いま合格している場面が逆に悪くなるおそれはありますか？
```

## プロンプト④：v1 と v2 を比べる

v2 の採点が終わったら、同じチャットで実行してください。

```
v1 と v2 の採点結果を比べてください。

- 合格数とスコア平均は、それぞれどう変わりましたか？
- v1 では合格していたのに、v2 で不合格になった場面（退行）はありますか？ あれば、その原因は v2 で書き足した指示にありますか？
- 次（v3）で直すべき原因を1つ選ぶとしたら何ですか？
```

## 時間が余ったら

- **モデルを替えて比べる。** 指示は v2 のまま、claude.ai のモデル選択で別のモデルに切り替えて、同じ10件で測ってみましょう。
  速いモデルでも合格数が変わらないなら、そちらで十分だと判断できます。これも評価があるからこそできる判断です。
- **自分の場面を増やす。** ステップ2で足した場面やClaude が提案した場面を加えて、v2 で測り直してみましょう。
  場面が増えると合格数の割合が下がることがあります。それは指示が悪くなったのではなく、**見えていなかった弱点が見えた** ということです。
- **改善例と見比べる。** [`solutions/prompt-v2-example.md`](solutions/prompt-v2-example.md) に改善例があります。
